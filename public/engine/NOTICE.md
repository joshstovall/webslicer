Local modification: in kiri-work.js, the worker pool size expression
`Math.max(4,Math.round(nY*.75))`
is replaced with
`Math.min(4,Math.max(2,Math.round(nY*.5)))`
to limit CPU/memory use on high-core devices. The worker and pool bundles also resolve kiri-geo.wasm relative to their module URLs so deployment under a subdirectory works. The engine bundle additionally exports its existing worker client as `engineClient`; the bridge uses it to synchronize and slice multiple widgets before joint path planning. Additional path-planning modifications are described below.

Purge block placement patch: `mkrec` in the FDM preparation path now receives a separate consecutive `blockIndex` for its XY location. It continues to retain the actual extruder index for tool selection and nozzle properties. The original worker used the extruder ID as its physical block offset, pushing high-numbered AMS slots beyond the bed. The block index is retained when rebuilding a belt purge block. The integration regression covers slots 8 and 16 and all four U1 heads. This is a local modification to the MIT-licensed Kiri:Moto worker; its updated checksum is recorded in `vendor-manifest.json`.

The application's separate material-preparation worker uses the npm dependency `manifold-3d` 3.5.4 (Apache-2.0). Vite bundles its JavaScript and WebAssembly locally; package-lock.json records its package integrity. Its license is included at `public/wasm/MANIFOLD-LICENSE.txt`. This is separate from the Manifold runtime embedded in Kiri:Moto.

Bed-aware purge planning: the worker imports the original Stratum helper `purge-planner.js`. It packs individual blocks into free bed space using model/support bounds and adhesion clearance, and sizes them from actual sliced heights, active directional purge requirements, filament flow and the pinned engine's extrusion cross-section. Empty sliced widgets and unused support tools no longer reserve blocks. The initial selected tool does not consume a change block; real tool changes do. Tool order prioritizes finishing the current tool before selecting a different tool, and exhausted block capacity fails explicitly. Preparation promise rejections are forwarded to the client; the bridge propagates preparation/export errors and releases the frame. See `docs/purge-planning.md` for behavior and limits.

`scripts/patch-purge-planning.py` reproduces this incremental worker modification from release `0559fa3`, failing if its exact patch targets differ. The worker checksum and local helper/bridge checksums are recorded in `vendor-manifest.json`. Upstream MIT notices remain intact.

Metered tower patch: `scripts/patch-metered-purge.py` adds an adapter to the existing non-belt purge function. The original Stratum `planPurgePaths` helper emits exact transition-priming paths separately from perimeter/foundation/sparse structural paths, with complete first-layer foundations and alternating row direction. Capacity reserves space for both sets of tracks. Belts retain the upstream path and are not exposed by the application's supported profiles. The incremental worker patch reproduces from release `93245f3`, fails on unexpected source, and preserves all upstream MIT notices. Updated runtime/helper hashes are recorded in `vendor-manifest.json`.

Tower-height patch: `scripts/patch-tower-height.py`, reproducible from `0786993`, calls the original Stratum `trimPurgeTower` helper before non-belt output is assigned for export. It interprets the engine's modal feature labels, retains foundations/structure through the last actual priming layer, then removes later tower extrusion and travel while preserving model records and layer metadata. The same helper module now supports explicit per-plate placement using machine XY coordinates converted to centered packing coordinates. Manual blocks use the automatic planner's model/support/adhesion/reserved-area checks and fail without relocating the requested position. All upstream MIT notices remain intact; worker/helper hashes are in `vendor-manifest.json`.


Bridge-cooling patch: `scripts/patch-bridge-cooling.py`, reproducible from `f46e633`, imports the original Stratum `bridge-cooling.js` helper and emits bridge-state markers at deposition/tool/layer boundaries. The helper compares solid-fill paths against prior sliced footprints across all widgets, including holes and overlaps, without changing path coordinates or extrusion. The patch also aligns every application's widget starting grid to the configured first-layer height; previously elevated parts could use a different grid and create extra tower-only layers. Belt behavior is not exposed by the supported profiles. Helper and worker hashes are recorded in `vendor-manifest.json`; upstream MIT notices remain intact. No Bambu/Snapmaker firmware implementation is included.

Adaptive material layers: the original Stratum `layer-plan.js` helper creates one plate-wide schedule from prepared geometry. `scripts/patch-adaptive-layers.py` reproduces the incremental MIT-licensed worker modification from `9debe20`: consume shared midpoint/height pairs, preserve physical print tops and actual extrusion heights, use 1 µm grouping precision, and exclude heightless synthetic end markers from preparation. Real empty slices beneath elevated parts remain. See `docs/adaptive-layers.md` for the algorithm, precision and tests. Worker, bridge and helper hashes are recorded in `vendor-manifest.json`.

Manual layer curves: `layer-plan.js` now also builds a shared schedule from bounded, ordered user control points. It solves the midpoint target equation by bounded bisection and preserves integer-micron tops/heights. The existing adaptive worker integration consumes these schedules unchanged. The same original helper is used by the editor for preview/validation.

Raft state and tower bases: `scripts/patch-raft-tools.py`, reproducible from `e885dfa`, assigns generated raft slices to the configured support/model tool, initializes the planner/export tool state accordingly, includes raft-only tools in purge capacity, and meters the first real tool transition. When a tower is needed, it adds structural paths at every raft level and across the model separation gap. Model gaps remain unchanged; original modal feature labels and retraction state are preserved. The shared trimming pass still removes unused tower paths. This modifies the MIT-licensed Kiri worker and original Stratum helper; all upstream notices remain intact. Runtime hashes are in `vendor-manifest.json`.

Spatial infill modifiers: the original Stratum `modifier-infill.js` helper partitions existing infill areas using the pinned engine's polygon intersection/difference and pattern generators. It excludes existing surface solids, preserves original walls, resolves later-mask priority, and emits full-density parallel lines where requested. `scripts/patch-modifier-infill.py` reproduces the incremental MIT worker modification from `e0dea91`: slice mask volumes at each model plane, await bounded per-layer processing, and bypass whole-layer dense-fill/cache shortcuts for affected objects. The bridge uses numeric arrays for JSON-copied annotations. All upstream notices remain intact; see `docs/modifier-meshes.md` and the runtime manifest.

Support-contact modifiers: the original Stratum `support-modifiers.js` helper selects new underside contacts with closed mesh volumes, applying ordered enforcers/blockers before native downward support projection. `scripts/patch-support-modifiers.py` reproduces the incremental MIT worker changes from `56f0778`, including exact fixed-layer physical tops and micron grouping instead of rounding midplanes to hundredths. The bridge separates support and infill annotations. This does not implement branching trees: the pinned native tree flag is a no-op. See `docs/support-modifiers.md`; updated hashes are recorded in the runtime manifest and all upstream notices remain intact.

The same support patch accounts for nearby printable solids in contact generation, downward projection and support clearance. Neighbor cross-sections prevent automatic/enforced supports from extruding through other material regions or unrelated models. XY bounds filter relevant neighbors before dispatch. Material assignments and modifier ownership remain separate from physical occlusion.

Support surface painting: the original MIT Stratum `support-paint.js` helper sweeps downward painted triangles through successive contact intervals, clips their geometry to each interval and projects the resulting polygons into the native contact pipeline. Paint enforcers/blockers apply after volume masks and before physical-part occlusion. The bridge carries independent surface annotations without converting them into printable material. `scripts/patch-support-paint.py` reproduces the incremental worker changes from `0abe6a8`, supplying polygon construction and paint records and allowing 0.0006 mm tolerance in automatic shadow sampling to match native micron-rounded vertices. This preserves upstream MIT notices; checksums are in `vendor-manifest.json`.

Regional process modifiers: the original MIT Stratum `process-modifiers.js` helper uses native closed cross-sections to split model extrusion moves at mask boundaries, preserving holes and independent speed/flow priority. It runs after native planning and before bridge classification/export. Model ownership prevents overrides from reaching unrelated parts, supports, adhesion or purge paths. Filament flow limits and whole-layer cooling run afterward. `scripts/patch-process-modifiers.py` reproduces the incremental worker changes from `62a3f76`; it also includes support base polygons in raft/skirt footprints and reports an empty raft footprint instead of dereferencing a missing start point. All upstream notices remain intact; updated hashes are in `vendor-manifest.json`.

Regional wall modifiers: the original MIT Stratum `wall-modifiers.js` helper regenerates native whole-section shell variants, clips their centerlines to count regions, preserves thin-wall metadata, and assembles the matching fill offsets. Skin projection and travel routing use physical model boundaries. The original interval splitter in `process-modifiers.js` now also resolves wall counts. `scripts/patch-wall-modifiers.py` reproduces the incremental worker modifications from `d20016e`, including explicit open-path planning, depth-preserving regional shell generation and ordering, retaining compensated zero-area/nonzero-length thin walls during decode, and disabling stale sparse-infill caching. No new upstream source is bundled; all existing MIT notices remain intact. See `docs/wall-modifiers.md` and `vendor-manifest.json`.

Regional surface skins: the original MIT Stratum `skin-modifiers.js` helper resolves independent top/bottom counts against actual neighboring layer sections, unions linked material geometry, clips to current wall offsets, and guards short fill joins against crossing excluded skin regions. `scripts/patch-skin-modifiers.py` reproduces the incremental worker patch from `fb7e0d6`, replacing duplicate solid passes for affected owners, preserving small skin regions, and disabling stale infill caching. Existing upstream MIT notices remain intact. See `docs/skin-modifiers.md` and `vendor-manifest.json`.

Branching tree supports: the original MIT Stratum `tree-supports.js` planner combines contact roofs and physical obstacles across the plate, grows tapered/merging sections with bounded layer-to-layer reach, and routes toward model-top landings or around obstacles. Shared sections are emitted only once and refilled with native support paths before raft and purge planning. `scripts/patch-tree-supports.py` reproduces the incremental worker hook from `17e9c4c`; the bridge displays its planning stage. This supplies actual branching geometry independently of the pinned engine's otherwise unused tree flag. No Orca/Prusa implementation is copied or bundled. Existing upstream MIT notices remain intact. See `docs/tree-supports.md` and the updated runtime manifest.

The bundled upstream engine/worker/pool code is unchanged by this packaging step. See `scripts/runtime-bundle.mjs`, `scripts/verify-runtime.mjs` and `docs/runtime-delivery.md`.
