# Spatial infill modifiers

Select an object and open **Object modifiers** in Object properties. Add a cube, cylinder or sphere, or import a closed STL/OBJ/3MF volume. The translucent amber preview shows the modifier without adding printable geometry. Imported model colors are not used as filament assignments. Positions, rotations and scales are relative to the owning part; linked material parts share its modifiers. View buttons frame the object and volumes in isometric/front/top/right views. Phones use a bottom drawer with the preview above it.

Choose **Infill density and pattern** as the modifier effect. Each infill volume selects an infill density from 0–100% and a pattern. Later volumes take precedence wherever their cross-sections overlap, including 0% overrides. Earlier/Later changes this order. Within an assembly, owning parts follow project order, then each owner's modifier order. Hidden owners and disabled modifiers do not participate. A volume can extend beyond the object or plate: only its intersection with the object's existing infill area changes. Walls, surface skins, supports and purge structures remain separate.

Apply commits the draft as one undo step; Cancel discards it. Geometry, order, settings and enabled state survive portable projects and IndexedDB recovery. Parent transforms and duplication carry modifiers. Assembly linking/rebasing preserves their world placement, including rotated and nonuniformly scaled parents. Material-preserving cuts, splits and height assignments retain the masks on the resulting objects; masks move with grounded/flipped pieces. Disconnected pieces receive their own copies so each can subsequently move independently. Exporting a plate as STL exports printable models, not modifier volumes.

## Engine behavior

`attachModifiers` uses source-object identities retained through material preparation. A modifier reaches only its owning object/linked assembly, including its painted material regions. It does not become a printable material, change the model's height, reserve purge-tower space, or affect unrelated objects.

A local Manifold worker checks enabled volumes for closed, consistently oriented meshes before the slicing engine starts. The bridge passes explicit numeric arrays because the engine's annotation copier uses JSON serialization. Each worker slices modifier cross-sections at the exact model sampling plane. Modifier work runs one layer at a time to bound intermediate memory; native sparse-infill caching is disabled for affected objects.

The original `modifier-infill.js` adapter partitions the existing fill area with polygon intersection/difference. It first excludes existing surface solids, then assigns exclusive areas from highest-priority mask to lowest, finally applying the base process to the remainder. Each region invokes the native infill pattern generator against its clipped area. A full-density region uses alternating parallel lines at the configured line width. Empty regions receive no infill. The adapter does not split the model into artificial solid objects or add perimeter walls at modifier boundaries. Original top/bottom and projected solid areas remain intact even under a zero-density mask.

Fixed, automatic adaptive and manual layer schedules use the same path. Raft offsets are added later by preparation, so mask Z remains relative to the model bed. Material assignments and per-spool flow/cooling limits continue through the existing G-code pipeline.

The incremental MIT-licensed worker patch is reproducible from release `e0dea91` with `scripts/patch-modifier-infill.py`; source/runtime hashes are recorded in `vendor-manifest.json`. Upstream reference: pinned Kiri:Moto [FDM slice processing](https://github.com/GridSpace/grid-apps/blob/d138275bbe9d4e4030d8cb8b2dcf66607da9295a/src/kiri/mode/fdm/work/slice.js) and [polygon operations](https://github.com/GridSpace/grid-apps/blob/d138275bbe9d4e4030d8cb8b2dcf66607da9295a/src/geo/polygons.js).

## Current bounds and remaining scope

This editor implements **regional top/bottom skin counts** (see `skin-modifiers.md`), **regional wall counts** (see `wall-modifiers.md`), **infill density and pattern**, **regional speed/flow** modifiers (see `process-modifiers.md`), and **support-contact enforcer/blocker** modifiers (see `support-modifiers.md`). Direct modifier transform gizmos remain unfinished parts of the broader slicer goal. Independent support surface painting is described in `support-paint.md`. Infill modifiers are incompatible with spiral vase mode and produce an explicit preflight error instead of being ignored.

Each owner supports up to 32 modifier volumes with a combined 500,000 triangles. Coordinates and positive transforms must be finite, settings validated, and each enabled volume must be closed with positive volume. These limits bound imported data; complex geometry can still require substantial browser memory. An edit that consolidates masks beyond those per-part limits fails before replacing the original objects. Sub-layer details can disappear at the model's sampling planes. Imported textures/process settings and automatic orientation are not part of this implementation.

Tests compare actual exported paths, including unchanged wall segments, zero/full-density regions, priority overlaps, untouched heights outside a mask, a rotated nonuniform torus with a retained hole across two tools and adaptive layers, and rejection of open volumes. Every supported pattern is checked against its mask, with unchanged top/bottom skin paths under zero-density overrides. Core checks cover portable validation, world-space transforms, assembly ownership, hidden owners, disabled masks and cut/ground preservation. Desktop/phone UI checks cover cancel, numeric editing, recovery, undo/redo, portable download and actual slicing; phone coverage imports an STL volume. These establish software behavior, not physical print quality.
