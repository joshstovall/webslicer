# Regional top and bottom skins

In **Object modifiers**, add or import a closed volume and select **Top and bottom skins**. Cyan volumes can override top and bottom solid-layer counts independently, from 0–30. Zero removes that skin inside the volume; walls and infill retain their own settings. A region with zero skins and 100% infill still prints solid material. Disabling one override inherits an earlier applicable volume or the base process. Later enabled overrides win separately for top and bottom.

Counts apply at each destination layer inside the volume. A top count of three checks the next three actual layers for an exposed surface; a bottom count checks preceding layers. Thus a height-limited volume affects only layers it intersects, and changing a count does not create a new physical surface at the volume boundary. On adaptive/manual schedules, these are layer counts, so their thickness in millimeters varies with the schedule.

Positions/rotations/scales are relative to the owning part. Linked material parts share volumes; unrelated objects do not. The controls, meshes, order and enabled state survive undo/redo, recovery, portable projects, parent transforms, and material-preserving cuts/splits. Imported STL/OBJ/3MF volumes use the same closed-volume validation and limits as other modifiers. Spiral vase mode rejects enabled modifiers.

## Geometry and planning

`skin-modifiers.js` replaces the native solid-layer and projected-skin passes only for owners with active skin settings. It uses existing native polygon operations and line filling. Skin areas start from current `fill_off` boundaries, including regional wall counts. For each requested count it intersects every intervening physical cross-section, then subtracts the material that remains covered. This detects top caps, ledges, undersides and internal cavities without projecting through an air gap. A bounded neighborhood cache releases sections older than the maximum 30-layer look-behind window.

Physical sections include the union of all linked material parts, using the plate's fixed, adaptive or manual sampling grid. A filament boundary inside a continuous object therefore does not create an exposed top/bottom surface. An unrelated object cannot hide a linked object's surface. Raft offsets are added after this calculation, so modifier coordinates remain in model space.

Top/bottom regions are partitioned independently with polygon intersection and difference. The resulting surface/projected regions pass through native fill-angle hints and solid line generation; their areas are excluded from sparse infill. Native short-line midpoint shortcuts and connecting extrusion are allowed only when the complete move stays within the selected skin area. This prevents short connectors from bridging a zero-skin slot or crossing a modifier hole. Infill caching is disabled for affected owners, and the small-area threshold is reduced for explicit regional skins. Independent full-density infill remains dense even when skins are zero.

Wall paths are not regenerated by this effect. Regional wall, infill and speed/flow effects can coexist; spool limits, support generation and cooling retain their respective pipelines. Surface flags reflect actual exposed skin areas.

The incremental MIT worker patch is reproducible from `fb7e0d6` with `scripts/patch-skin-modifiers.py`; current source/runtime hashes are in `vendor-manifest.json`. Native API references are pinned [solid-layer processing](https://github.com/GridSpace/grid-apps/blob/d138275bbe9d4e4030d8cb8b2dcf66607da9295a/src/kiri/mode/fdm/work/slice.js), [path preparation](https://github.com/GridSpace/grid-apps/blob/d138275bbe9d4e4030d8cb8b2dcf66607da9295a/src/kiri/mode/fdm/work/prepare.js), and [polygon operations](https://github.com/GridSpace/grid-apps/blob/d138275bbe9d4e4030d8cb8b2dcf66607da9295a/src/geo/polygons.js). No upstream source was newly bundled; existing MIT notices remain intact.

## Verification and limits

Real-engine checks cover independent zero/count priority, density preservation, unchanged walls, narrow excluded slots, hollow rotated volumes using independent triangle-ray containment, exposed ledges, stacked color parts, adaptive/manual counts, air gaps, supported raft offsets, and combined modifier effects. Desktop/phone tests cover controls, undo/redo, recovery, portable downloads and actual G-code exports. Core checks cover validation, independent priority, guarded joins, world coordinates and cut preservation.

The shared limits of 32 modifier volumes and 500,000 modifier triangles per owner apply. Large linked assemblies and intricate surfaces can still be expensive; the maximum count is 30. Details below the sampling/grid precision may disappear. Counts are vertical layer depths, not a guarantee of constant normal thickness on a slope. These checks establish software behavior, not physical print quality.

Direct modifier handles, branching tree supports, fuller project/process/texture import fidelity, STEP, polygon packing, additional printer/material/connectivity controls, large-model/mobile/offline reliability, physical printer validation and the final broader requirement audit remain unfinished.
