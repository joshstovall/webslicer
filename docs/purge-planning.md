# Purge tower planning

When a plate uses multiple filaments and the tower is enabled, Stratum reserves one block per possible color change in a layer. The planner searches the entire rectangular build plate, including gaps between objects. Individual blocks can occupy separate free regions. It projects every model triangle onto the bed, unions generated normal/tree support outlines, and reserves adhesion clearance, the deposited line width, and spacing between blocks. Planned raft/skirt extrusion paths are also reserved: those paths can bridge gaps or fill openings that are empty in the model. A plate without sufficient room fails with a specific message; it does not export an off-bed or overlapping tower as a fallback.

The tower blocks remain square, but obstacles use complete polygon outlines, including holes and nested islands. Automatic placement can use frame openings and concave gaps. Candidate generation samples contour vertices and bounds; acceptance checks the complete contours. The finite greedy search does not prove that every physically possible arrangement has been found. A failed search offers manual positioning or rearrangement. Manual positioning uses the same full-contour and clearance checks. Existing Bambu/U1 presets use rectangular beds; belt printers are outside this adapter.

The pinned Bambu X1C/P1S/P1P profiles exclude the 18 × 28 mm front-left corner. Tower packing avoids it, the viewport marks it, model validation reports overlaps, and Arrange preserves clearance even after centering. Generated extrusion segments are checked against the reserved region, including line width and segments crossing the region with both endpoints outside. The limit is derived from printer identity so older projects also receive it. A1/A1 mini profiles explicitly have no such exclusion. Sources: the pinned [X1C](https://github.com/bambulab/BambuStudio/blob/79df7ae309be398ed30c9f397c13c9911c2edc57/resources/profiles/BBL/machine/Bambu%20Lab%20X1%20Carbon%200.4%20nozzle.json), [P1S](https://github.com/bambulab/BambuStudio/blob/79df7ae309be398ed30c9f397c13c9911c2edc57/resources/profiles/BBL/machine/Bambu%20Lab%20P1S%200.4%20nozzle.json) and [P1P](https://github.com/bambulab/BambuStudio/blob/79df7ae309be398ed30c9f397c13c9911c2edc57/resources/profiles/BBL/machine/Bambu%20Lab%20P1P%200.4%20nozzle.json) machine profiles. This does not complete the broader firmware/physical-limits audit.

The initial tool prints without consuming a color-change block. The first actual change and later changes receive tower extrusion before model/support extrusion. Current-tool parts are completed before changing tools. Unused support tools and empty sliced widgets do not reserve blocks. Unused blocks receive structural infill through the final required tool-change layer. A capacity overrun fails explicitly rather than silently skipping a purge.

## Manual placement per plate

In **Manage filaments → Tower placement**, choose **Manual** to set the first block’s center in machine X/Y millimeters. Additional blocks extend along the selected positive X or Y direction, spaced by the computed block size plus line width and 1 mm. Machine coordinates include profile origin offsets, including U1’s +0.5/+1 mm; the first block appears at the requested exported XY coordinates. Slicing computes the full footprint from the actual layers, material flow and purge budgets.

Manual placement is stored separately for each plate, survives recovery and portable project downloads, and participates in project history. Deleting a plate removes its placement so a new plate with the same ID starts with Automatic placement. Choosing Automatic removes the selected plate’s manual override. Existing projects keep automatic placement.

Every manual block must fit the bed with clearance and avoid all model/support/adhesion footprints and reserved areas. A collision reports the failing block and stops slicing; it never silently relocates the tower. Change its center/direction or return to Automatic, then slice again. Changing printers or purge settings preserves the requested coordinates and validates them against the new footprint. The current manual controls use numeric coordinates rather than viewport dragging. An opening is usable only when the entire padded tower block clears the projected model, supports and adhesion.

## Independent volume budgets

**Tower priming volume per change** and its directional overrides now control metered priming paths. Each transition deposits its configured volume, with a 0.02 mm³ reserve for coordinate/extrusion rounding. A final audit after per-filament flow adjustment accepts at most 0.05 mm³ deviation and rejects both insufficient and excess priming. E-only recovery, vendor machine routines and structural tower paths do not satisfy this check.

Bambu profiles have a separate **Station flushing volume per change** and a separate directional override for the selected from/to pair. Those values populate the pinned official template's flush-length variables; changing tower priming does not change station flushing. Station settings allow 0–2000 mm³; tower priming allows 1–2000 mm³. The machine's loading/calibration routines may extrude additional material. The pinned P1S template also adds 2 mm of filament for spillage compensation inside a separate flush region. The controls do not claim to eliminate those firmware costs. U1 independent heads use the tower budget; Bambu station settings do not replace U1 firmware priming.

Existing projects migrate their old default and directional purge values into independent copies of the station settings, preserving their prior macro requests. New edits then change only the selected budget. Removing an unused last filament clears both sets of overrides referring to that slot. Resetting a directional value uses its own budget's default.

## Tower structure and capacity

The largest active transition still determines the reserved footprint. Capacity uses the smallest actual sliced layer height, calibrated incoming filament flow, line width and the pinned exporter's `pi * lineWidth * layerHeight / 4` cross-section. The footprint reserves room for structural tracks as well as priming; unused slots and their overrides do not enlarge it.

Every block receives a closed perimeter. The first layer receives a complete foundation, and later layers retain approximately one in six interior rows plus the edge row, alternating their orientation by layer. Priming occupies separate rows up to the required length; a partial last row is cut geometrically rather than under-extruded. First-layer unprimed rows complete the foundation; later unused dense rows are omitted. Unused blocks receive the same layer's structural paths. All these paths finish before model/support printing resumes. Insufficient calculated path capacity fails explicitly.

G-code labels priming as `purge tower` and the perimeter/foundation/sparse rows as `purge tower structure`. Both appear as tower geometry in the viewer, but only priming counts against the exact transition budget. Total tower consumption therefore includes additional structural material, particularly on the first layer. This distinction saves dense fill on lower-volume transitions without pretending the supporting tower is free. The geometry has software coverage for complete foundations, non-overlapping priming/structural rows, alternating support rows, thin layers and low flow. Structural tower printing now stops at the final layer with actual priming. Foundations and sparse layers below a later change remain intact. The planner removes both extrusion and travel records above that layer before the exporter calculates XYZ/E, retaining model paths and per-layer height/parameter metadata. If there is no actual priming, it removes all tower paths. Empty tower-only terminal layers are removed as well. Its physical strength across materials/printers has not been verified.

## Raft tools and tower foundations

Rafts use the configured support filament when supports are enabled; without supports they use the first model's filament. The engine now selects that tool at startup, emits all raft paths with it and carries the state into the first model/support transition. A raft tool participates in directional purge capacity even when the geometry needs no generated supports. This removes an unintended switch to slot 1 on sparse nonzero-slot jobs.

For jobs requiring a tower, structural paths are added to each existing raft layer and to a tower-only layer spanning the raft-to-model separation gap. The model keeps that gap; the tower has a continuous base from the bed. Foundation paths use the raft tool, follow existing layer heights and reserve no transition priming volume. They participate in the usual flow limiting, bed checks and exact priming audit. Modal feature labels and end-of-layer retraction are preserved. The existing trimming pass removes all tower-only paths if no actual priming occurs later.

`scripts/patch-raft-tools.py` reproduces the incremental worker change from `e885dfa`. Browser regressions check first-tool identity, absent unused slot 1, bed-to-model tower layers, nonzero dedicated support slots with and without actual supports, single-material rafts, and Bambu/U1 exports. Physical raft and tower performance remains unverified.

## Geometry and resource limits

The original `purge-footprints.js` helper runs inside the isolated slicing worker after generated support interfaces and raft/skirt paths exist. It projects full triangles rather than sampling slice tops, so geometry between layer planes is retained. Fresh native polygons are unioned and offset; source model and support polygons are not modified. An overhanging roof blocks the area below it even when the tower would stop below that roof. This conservative full-height reservation does not simulate nozzle/head clearance for sequential printing.

Projection yields between triangle batches, support layers and adhesion batches. Cancelling slicing removes the isolated worker, including native geometry work. Limits are two million input triangles, two million support vertices, 250,000 planned adhesion segments, 250,000 final outline vertices, 200,000 candidate visits/overlap queries and eight million boundary edge checks. Exceeding a limit fails with an actionable message. These work bounds are not a guaranteed memory budget on mobile devices.

This planner locates the tower during slicing. Object Arrange still does not jointly reserve future generated support and tower envelopes. Physical print validation, broader packing optimization and real-device stress testing remain part of the full slicer goal.
